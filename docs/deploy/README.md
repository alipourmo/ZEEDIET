# محیط‌های اجرای ZeeDiet

برای نگهداری و انتشار فقط **یک نسخه از کد برنامه** داریم و دو پیکربندی استقرار. شاخه یا fork جداگانه لازم نیست؛ تغییرات برنامه از همان مخزن می‌آیند و هر محیط متغیرهای خودش را دارد.

| محیط | مناسب برای | Runtime | دیتابیس | وضعیت |
|---|---|---|---|---|
| **سرور اصلی** | استفادهٔ واقعی پس از تأیید آماده‌بودن | Linux + Nginx + PHP-FPM 8.4 | MySQL 8 | مسیر production؛ باید backup، worker، scheduler و SMS واقعی تنظیم شوند |
| **آزمایشی آنلاین** | آزمایش رابط و workflow با دادهٔ ساختگی | کانتینر FrankenPHP در Vercel | Supabase PostgreSQL، schema `zeediet` | آزمایشی؛ بدون اطلاعات واقعی و بدون تضمین عملیات production |
| توسعهٔ محلی | کدنویسی و اجرای تست | PHP/Laravel | SQLite | ابزار توسعه است، نه محیط انتشار |

## کدام را انتخاب کنم؟

- برای هاست/سروری که قرار است کار واقعی کلینیک را انجام دهد: [استقرار VPS/هاست + MySQL](vps-mysql.md).
- برای دیدن آنلاین برنامه و تست اولیه: [استقرار آزمایشی Vercel + Supabase](vercel-supabase-fa.md).
- برای اجرای روزمرهٔ کد روی لپ‌تاپ: دستورهای بخش «اجرای محلی» در [README](../../README.md).

تفاوت دیتابیس و runtime با environment variables تنظیم می‌شود؛ کپی‌کردن برنامه به نسخه‌های جدا و همگام نگه‌داشتن آن‌ها لازم نیست. ابتدا روی محیط آزمایشی بررسی کنید، سپس همان commit را پس از backup و بررسی، روی سرور اصلی منتشر کنید.
